# 4. The Chrome extension

Lizard moved from an idea for a timer into a browser extension so that a session could be reviewed in the same environment where much computer-based work happens. A browser product brought a more immediate interface, but also new questions: what can an extension observe, how should a session feel across different kinds of activity, and how much confidence should a summary invite?

The extension format also made reliability part of the product experience. A session can outlast a small popup, and browser pages and media players do not all behave alike. These constraints encouraged the project to think about sessions as more than a timer screen, while also making clear that broad browser reach creates real privacy responsibilities.

The journal intentionally stays at this product level. It does not publish implementation files, permission configuration, message formats or internal algorithms. The point is to explain why reliability and restraint mattered, not to duplicate the private technical manual.

As the product matured, the initial active/reading distinction grew into Work, Reading and Video sessions, with a timeline and a history to revisit. The current experience is described in [features and experience](../product/features-and-experience.md).
